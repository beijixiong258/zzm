# AIcademiya

AIcademiya 用于教师备课与学生学习。教师创建课程、上传材料生成讲义，在预览中修改并发布；学生阅读、作答并与 AI 助教对话，教师查看进展并给出反馈。任务始终归属于课程，支持归档、恢复和彻底删除。

## 部署

安装并启动 Docker，确认可以使用 `docker compose`。程序已提供数据库、端口、存储目录和模型的默认配置。

1. 编辑根目录的 `application.yaml`，填写 `app.ai.api-key`。默认使用硅基流动接口和 `Qwen/Qwen3.8-27B`；使用其他兼容接口时，同时修改 `provider`、`base-url` 和 `model`，其中 `provider` 可设为 `openai`。
2. 在项目根目录执行：

   ```powershell
   docker compose up -d --build --wait
   ```

3. 打开 `http://localhost:5173`；部署在服务器上时，将 `localhost` 换成服务器地址。首次进入后，通过管理员入口创建首位管理员，再添加教师和学生账号。

只需维护一份 `application.yaml`，无需准备 `.env`、`config.json`、外部数据库数据卷或手工导入表结构。首次使用空数据卷时，MySQL 自动建库并执行随程序提供的表结构；已有数据卷直接复用，不重置数据或密码。

网页和 `/api` 使用同一访问入口，对外只开放 `5173`。数据库与后端在容器网络内通信，无需填写服务器 IP、跨域来源或单独开放接口端口。

## 配置

常用的 AI 配置位于根目录 `application.yaml`：

```yaml
app:
  ai:
    provider: siliconflow
    base-url: https://api.siliconflow.cn/v1
    model: Qwen/Qwen3.8-27B
    api-key: '你的 API 密钥'
```

其他设置保持默认即可。修改配置后执行 `docker compose restart backend` 生效。需要演示教师和演示学生入口时，在 `app` 下添加 `demo-enabled: true`。

如需修改首次建库的数据库密码，同步修改 `application.yaml` 中的 `spring.datasource.password` 和 `compose.yaml` 中的 `MYSQL_ROOT_PASSWORD`。使用已有数据库时，YAML 中的账号密码应与该库一致，修改配置不会改变库中已有的密码。

## 使用

1. 教师新建课程，在课程信息界面直接填写或通过对话整理教学要求。
2. 在课程中创建任务，将课件、练习单、参考答案和提示词一并上传，处理完成后生成讲义。
3. 预览并修改讲义、题目和辅导要求，保存后模拟学生视角或首次发布。任务发布后，保存修改会直接更新学生看到的内容；重新生成的讲义先供教师检查，再点击“更新任务”。
4. 学生登录后学习、作答和提交，教师在任务中查看进展和反馈。

课程标题右侧的操作菜单提供“删除课程”。确认后会一并删除该课程的全部任务、发布内容、学习记录、对话和成员关系，账号与其他课程保留；材料文件进入回收目录，共用文件保留。

界面支持简体中文和英式英语，英文日期按日、月、年的顺序显示。切换界面语言不会翻译已保存的教学内容。新生成的教学说明按所选教学语言使用规范简体中文或英式英语，原始材料、题目和选项保留原文。

参考答案按题目与选项的含义对应，原有答案说明保留在教师可见的解析中。无法明确对应选项的参考答案保留原文，可在预览中编辑，AI 助教也会结合本题内容理解。

每项任务只维护一份当前发布内容，更新时直接覆盖，不使用发布版本号。学生进度按任务统一查看，更新内容不会另建学习记录；旧作答、对话和附件保留在学习历史中。已删除或更改选项的题目，其旧答案可在作答历史中查看。

课程助手的对话记录保存在当前浏览器，不跨设备同步。内部指令、参考答案和未审核反馈不向学生展示。生成内容完整返回并通过校验后才会应用，不完整的结果不会应用。

## 停止、更新与数据保存

停止服务并保留数据：

```powershell
docker compose stop
```

更新程序后，在根目录重新执行部署命令。查看运行情况可执行 `docker compose ps`，查看日志可执行 `docker compose logs --tail=100`。

数据库、上传文件和文件回收目录分别保存在 `app_mysql-data`、`app_uploads`、`app_recycle` 数据卷中。正常停止或重建容器会保留这些数据。归档保留任务和学习记录，可恢复；彻底删除须在程序中确认，程序内无法撤销。

上传文件和回收文件的路径均相对于各自存储目录保存，不记录宿主机的绝对路径。已有数据库在启动时自动升级相关外键和旧路径记录，不重置课程与学习数据。

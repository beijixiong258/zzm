# AIcademiya

AIcademiya 用于教师备课与学生学习，以课程、教学任务和学习记录组织教学活动。教师维护课程信息、上传材料生成讲义，在预览中核对、修改和发布；学生阅读、作答、上传附件并与 AI 辅导员对话。系统提供形成性反馈，不自动形成正式成绩。

## 主要功能

- **课程管理**：创建课程，直接编辑或通过对话填写课程信息、学生情况和教学要求。
- **任务与讲义**：任务归属于课程。将课件、工作纸、参考答案和提示词一起上传，由 AI 识别用途并生成讲义、题目与辅导设置。
- **预览与发布**：核对正文、题目、选项、参考答案和辅导要求，使用学生视角模拟后发布。已发布版本与学生记录绑定。
- **教学跟进**：查看学生进展、学习记录和待审核反馈，确认完成或要求修改。
- **归档管理**：归档后学生无法从列表、历史、旧链接或附件入口访问；可恢复，也可在确认后彻底删除。

课程、任务及学习记录保存到 MySQL。教师课程对话与未发送消息保存在当前浏览器，不跨设备同步。内部教学指令、参考答案和未审核反馈不向学生展示。

## 部署条件

- Docker 与 Docker Compose 可用。
- 已准备好的 MySQL 数据卷 `app_mysql-data`，其中包含 `aicademiya` 数据库及程序所需表结构。此部署使用 MySQL 8.4 镜像，复用现有数据，不创建新数据库或重置数据库账号。
- 可用的 AI 接口、API 密钥与模型 ID。

SQL 初始化脚本关闭。数据库连接账号应具备程序正常读写及必要结构升级的权限。

## 配置

部署目录中准备以下文件：

| 文件 | 用途 |
| --- | --- |
| `compose.yaml` | 编排数据库、后端与前端服务 |
| `application.yaml` | 填写现有数据库的连接账号与密码 |
| `config.json` | 模型参数，可按 `config.defaults.json` 填写 |
| `.env` | AI 接口信息、访问来源及可选功能开关 |

在根目录创建 `application.yaml`，填写数据库的实际账号密码：

```yaml
spring:
  datasource:
    username: '数据库账号'
    password: '数据库密码'
```

该文件只读挂载到后端配置目录。账号密码直接写在 YAML 中，不需要导出数据库凭据环境变量；数字形式的密码也须加引号，避免丢失前导零。默认数据库连接地址为容器网络中的 `mysql:3306/aicademiya`。

在 `.env` 中填写实际 AI 配置与页面访问来源：

```dotenv
AICADEMIYA_AI_API_KEY=你的API密钥
AICADEMIYA_AI_BASE_URL=https://api.siliconflow.cn/v1
AICADEMIYA_AI_MODEL=你的模型ID
AICADEMIYA_ALLOWED_ORIGINS=http://服务器地址:5173
```

将接口地址、模型 ID 和服务器地址替换为实际值。访问来源填写浏览器使用的完整前端来源，多个来源用英文逗号分隔。未指定时允许 `http://localhost:5173` 和 `http://127.0.0.1:5173`。

演示入口默认关闭。如需专用演示教师、演示学生入口，可设置 `AICADEMIYA_DEMO_ENABLED=true`。演示账号产生的课程和任务同样会保存。

## 启动与停止

在部署目录执行：

```powershell
docker compose up -d --build --wait --wait-timeout 300
```

该命令构建镜像，并等待数据库、后端和前端依次通过健康检查。更新程序后使用同一命令重建。

| 服务 | 访问位置 |
| --- | --- |
| 前端页面 | `http://服务器地址:5173` |
| 后端接口 | `http://服务器地址:8001/api` |
| MySQL | 容器网络内 `mysql:3306`；宿主机管理端口为回环地址 `3307` |

首次使用且尚无管理员账号时，可通过登录页的管理员入口创建首位管理员。之后按实际分配的教师或学生身份登录。

停止服务：

```powershell
docker compose stop
```

停止后保留数据库和上传文件。Compose 项目名为 `app`。

## 使用流程

1. 教师创建课程，在课程信息界面填写或通过对话整理基本信息，然后保存。
2. 在课程中创建任务，将全部教学材料一起上传。处理完成后生成讲义。
3. 在预览中核对并修改讲义、题目与辅导要求，保存后进行学生视角模拟或发布。
4. 学生用邮箱密码或个人邀请码登录；课程加入码与个人登录邀请码用途不同。
5. 教师在任务的“更多操作”中查看学生进展、编辑任务、管理材料或归档任务。

每个任务必须属于课程。材料按课程管理，可在同一课程的任务间复用。

## 材料与生成状态

- 支持 PDF、Word、PowerPoint、Excel、EPUB、文本及图片，单文件最多 **25 MiB**，前端最多同时上传 3 份文件。
- PDF 按整份材料处理；完整文字层可本地提取，需要保留图像时按原页序准备页面图片。处理失败或内容不完整的材料不能用于生成或发布。
- 生成页面显示累计用时与已接收字符数。完整结果返回、解析、校验并应用后才算完成；中断或截断的半成品不会应用到讲义。
- 未提供选项的选择题会按开放题保留，并提示教师核对。未提供的开放题参考答案留空，由 AI 给出定性反馈。
- 本地 token 估算仅供参考，实际容量、用量与请求是否接受以上游服务返回为准。

## 数据保存与恢复

| 内容 | 保存位置 |
| --- | --- |
| 数据库 | 现有外部数据卷 `app_mysql-data` |
| 上传材料 | 数据卷 `app_uploads`，容器内 `/data/uploads` |
| 文件回收目录 | 数据卷 `app_recycle`，容器内 `/data/recycle` |
| 模型配置 | 宿主机 `config.json`，容器内只读 |
| 数据库凭据 | 宿主机 `application.yaml`，容器内只读 |

归档任务会保留版本、学习进度和对话，恢复后可继续使用。彻底删除仅适用于已归档且没有排队或运行中生成任务的项目，确认后删除任务及关联记录；课程材料保留，不再被其他内容引用的学生附件移入文件回收目录。程序内无法撤销彻底删除。

# AIcademiya

AIcademiya 面向教师备课、课程组织与学生学习，围绕 **Course（课程）— Task（教学任务）— LearningRecord（学习记录）** 工作。教师提供材料和补充提示词，由 AI 生成讲义、设计辅导并提取或生成练习；学生在获得授权的任务内阅读、作答、上传作品并与 AI 对话。

当前工作分支为 `cys`，应用版本沿用 **0.1.0**。技术栈为 **Vue 3 + TypeScript + Vite、Java 17 + Spring Boot + Spring AI + MyBatis-Plus、MySQL**。前端默认端口 **5173**，后端默认端口 **8001**。文件解析在 Java 后端内完成，AI 请求沿用硅基流动配置。

本文是当前应用的统一项目说明，已整合原有 README 和仍有参考价值的历史工具说明。已确认的产品范围、运行方式和验证结果统一在本文维护；协作约定见 [app/AGENTS.md](app/AGENTS.md)。

> 最近运行验证（2026-10-26）：已使用当前源码构建 Docker 前后端，完成启动、网页访问及演示教师登录；本次验证容器已停止，5173、8001、3307 端口已核验释放。原本机配置中的硅基流动 API Key 仍保留，但临时容器使用了未接入密钥的默认配置，本次没有验证真实 AI 请求。具体范围见文末当日记录；历史记录不代表当前服务仍在运行或全量业务已验收。

## 已确定的产品范围

- 界面只有简体中文和英文。界面语言与任务教学语言分别设置，AI 输出保持任务指定语言，不被界面翻译覆盖。
- 课程设置分为 **课程信息、学生情况、AI 辅导教师通用指令**。任务级要求统一通过一个“补充提示词”入口提供。
- 教师工作台提供自适应辅导、阅读与改写、练习与讲义入口，允许先保存资源，再复制到课程。
- AI 对话与讲义使用 **Markdown 富文本**。不接入 AI 生图服务；已上传的图片仍可作为学习材料。
- 应用上下文上限固定为 **64,000 token**。材料识别、生成讲义与每轮对话分别计算请求容量。
- 登录入口先选择“教师、学生、管理员”。教师和管理员使用邮箱密码；学生默认使用“用户名 + 个人邀请码”，也可切换邮箱密码。后端校验所选身份。个人邀请码与加入课程的口令用途不同。
- 教师预览复用学生页面及学习服务，支持讲义阅读、作答、附件、提交和 AI 对话，模拟记录不计入真实学生进度。

## 日常使用

### 教师

1. 在课程设置中填写课程信息、学生情况和通用教学指令；输入框中的灰色文字说明各字段的用途。
2. 上传文件或文件夹前，在“新上传材料的可见性”中选择“师生均可见”或“仅教师与 AI 可用”。课程材料库和任务编辑页均支持此设置；文件入队时固定其可见性，后续切换选项不改变已排队文件。前端最多同时上传 **3 个文件**；后端由 **2 个材料处理任务**并行处理，页面自动更新状态。
3. 选择任务材料。提取现有题目时，可以勾选多份来源材料；题目按来源保留，原材料未给出答案时不要求 AI 编造答案。
4. 任务编辑页只保留任务设置、材料选择和一个“补充提示词”入口。开场白、Markdown 讲义、学习计划及练习由 AI 生成；通过同一个提示词框要求 AI 修改，不再手工填写讲义或编辑学习计划、插图。重新生成按全部材料和当前指令生成新讲义，保留辅导设置；定向修改额外携带现有讲义并单独计算容量，超限时可以改用重新生成。生成进度自动更新，右侧直接呈现学生端讲义与对话操作。
5. 右侧默认显示 AI 生成的讲义与练习，点击“开始模拟”进入 AI 对话；使用“讲义与练习 / AI 对话”切换阅读、作答与聊天。修改提示词后点击“保存并刷新预览”，再开始新的模拟。模拟使用保存时的草稿快照，与学生端复用同一套操作和服务。
6. 发布任务后，学生进入不可变的发布版本。后续编辑草稿不会覆盖已经发布的内容或学生记录。
7. 在“学生进度”中查看作答、历史对话、附件及提交状态，给出教师反馈、要求修改或确认完成。

课程创建窗口提供顶部返回、关闭按钮和 Escape 退出；按账号、课程区分的草稿在输入时保存到本机浏览器，关闭、刷新后再次打开可恢复，成功保存到服务器后清除本机草稿。本机草稿不跨设备同步。材料库和任务页有顶部返回栏。上传按真实传输字节数显示百分比；服务器保存阶段、AI 生成阶段使用加载状态，文档解析显示已完成页数及当前页。

“AI 反馈”可设置为立即显示，或由教师审核后显示。待审核反馈不会通过学生接口暴露正文，教师可以修改后发布。评价标准可引导建议性反馈；正式评价与完成确认由教师决定。

课程外的“教师工作台”使用同一套任务与材料服务保存资源。课程响应通过布尔字段 `workspace` 区分普通课程（`false`）与工作台（`true`）。资源复用入口放在工作台资源列表中；复制到其他课程会建立新草稿和材料引用，不复制学生作答、对话、模拟记录或发布版本。

### 学生与邀请码

教师在课程的“管理班级”页面创建学生用户名和个人邀请码，邀请码只在创建或重置时显示。数据库保存其 BCrypt 摘要；重置或停用会使旧邀请码及该学生已有登录会话失效。

学生在登录页选择“学生邀请码登录”，输入用户名及个人邀请码。用户名不区分大小写，允许 3—64 位英文字母、数字、英文句点、下划线或连字符。加入课程的口令不能代替登录凭据。

学生可以上传文档或图片并关联到题目，选择附件随消息发送。附件属于具体学习记录，其他学生不能读取。重复上传保留为独立文件，作答保存时保留原答案版本；对话反馈与显式提交分别处理。

处理中或解析失败的已选附件可以取消勾选，不必等待解析成功才能继续发纯文本消息。提交前可移除本人的附件；移除保留逻辑标记与历史引用，记录操作时间和操作人，历史消息显示“已移除的附件”。事务提交后，后台每 30 秒将文件移入指定回收目录；正在解析的文件等待处理结束再移动，移动失败会重试。原文件不被永久删除。移除后该附件不再作为材料加入后续 AI 上下文，也不计入有效附件数量；已经形成的对话文字仍保留。已提交或已确认的记录须经教师要求修改后才能移除附件。

附件移除接口为 `DELETE /api/records/{recordId}/attachments/{attachmentId}?revision={revision}`，校验归属及记录版本，返回更新后的学习记录和 `removedAttachments` 标记。移除后的附件不能重新发送、下载或重试；不存在或属于他人的附件仍被拒绝，不通过忽略非法引用来恢复聊天。

当前对话默认最多 200 条消息，包含开场白及师生／AI 消息；新一轮会超过上限时返回 409，页面提示“开始新对话”。旧对话完整保存，但不再加入后续模型请求，不会自动删去最早 50 条消息。40,000 token 输入上限与 64,000 token 总上下文预算继续独立检查，可能先于消息条数上限触发。

新增作答快照及已结束会话逐条保存到 learning_record_history，主记录的历史 JSON 不再追加；已有 JSON 保持只读兼容。默认学习记录响应只含最近 5 条答案快照、最近 3 个会话摘要及 historyTruncated 标记。作答历史每页最多 50 条、会话目录每页最多 10 条，每段会话按 50 条消息分页，师生页面按需加载。教师可在监控页面分页查看附件移除记录。学生接口继续隐藏待审核反馈和教师私有字段。

接口为 GET /api/records/{id}/history?kind=answer|conversation|attachment&page=1&size=20，以及 GET /api/records/{id}/history/{historyId}/messages?page=1&size=50；后者也接受 current 读取当前对话。分页请求可携带 revision，记录变更后需重新加载。个人学习记录列表只返回摘要，不再包含全部答案和对话。

50／10 是分页读取上限，不是丢弃历史的保留条数。系统不按 180 天自动删除教学记录；单条历史超过 1 MiB 时写入告警。附件文件也不执行“7 天后永久删除”，由用户手动清空垃圾桶。

每条学习记录最多保留 100 个有效附件、默认总容量 500 MiB。上传通过数据库记录行锁串行核对配额，避免并发上传绕过限制；移除的附件不计入有效配额。文件回收只处理个人附件，移动前检查共享存储引用，不移动被其他材料复用的文件。上传与应用回收目录的总占用超过默认 10 GiB 时记录日志告警。

### 导出

仅学生可以导出自己的学习结果，格式为 UTF-8 Markdown（.md）。教师、管理员和教师模拟记录不提供导出。任务编辑页的导出区域、原任务文档导出接口及结构图图片导出入口已移除。

- 导出绑定学习记录所属的发布版本，包含学生可见的讲义、题目、当前作答、当前对话、教师反馈和有效附件链接。
- 不包含教师提示词、参考答案、评价标准或尚待审核的 AI 反馈正文。历史对话仍通过历史分页查看，当前导出不包含全部历史快照。
- 学生点击导出时先保存未保存的作答。附件和课程材料以需要登录及相应权限的链接引用，不嵌入文件。
- 接口为 GET /api/records/{id}/export?format=md；校验学生身份、记录归属及课程访问权限。教师或管理员请求返回 403，其他学生的记录不可读取，非 Markdown 格式返回 422。
- PDFBox、POI 继续用于上传材料解析。Markdown 导出不调用模型，不需要字体配置。

## 材料处理与输入容量

支持 **PDF、DOC/DOCX、PPT/PPTX、XLS/XLSX、EPUB、TXT/Markdown、PNG/JPEG/WebP**，单文件最多 **25 MiB**。默认最多处理 **300 个单元、300,000 个字符**；这些是文件处理范围限制，不是模型上下文长度。

### PDF：原生文本或整份逐页图片

PDF 以整份文件决定输入方式。所有页面都能完整用可用的原生文字层表达时，使用 PDFBox 在本地提取文字，并保留页码顺序。标题页不因文字少而被单独判为扫描页；真正空白的页面保留页序。只要有一页存在需要保留的图像、绘制图形、批注，或其文字层无法可靠提取，**整份 PDF 的全部页面都会按原页序转为 JPEG**，不混用“部分页面文字、部分页面图片”的输入。

**PDF 准备过程不进行 OCR，不调用视觉模型转录，也不产生模型用量。** 本地只检查文字层、渲染页面、裁剪明显的外围近白留白并计算 token 估算。裁剪保留非白内容和安全边距；无明显留白时保留整页。图片最长边沿用现有配置（默认 2,000 像素，最高 144 DPI），不会为绕过输入上限自动缩小图片或漏掉页面。

材料报告记录输入方式、总页数、已检查／准备页数、每页实际图片尺寸、裁剪位置、JPEG 字节数和图片 token 估算。原始 PDF 始终保留；不额外保存持久化页面图片。通过完整请求的预算检查后，按报告中保存的 DPI 和裁剪范围重新渲染 JPEG，通过 Spring AI 的多模态消息直接发送。页面标签包含材料 ID 和页码，供生成讲义、提取题目、修订讲义以及学生／教师模拟对话使用。

**超过 40,000 token 的材料仍可以上传和保存在材料库；超限的 AI 请求会被拒绝。** 课程材料库和任务编辑页的文件列表会直接显示“处理完成 · 超出 AI 输入容量”，并标出该材料的预计 token 占用和 40,000 上限。文字采用保守上界，图片 PDF 采用全部页面的图片估算；这里只统计单份材料，提示词、其他所选材料和对话历史仍由完整请求的预算检查统一计算。图片 PDF 的文本字段为空是正常结果，完整的页面报告可使其显示为“处理完成”。旧规则产生的 PDF 转录结果必须点击“重新处理”，不能继续作为新请求的材料正文；原文件、既有课程、学习记录和历史讲义保持原样。

POI 继续读取 Office 文字、表格、图片及图表／公式结构；EPUB 按阅读顺序提取章节和嵌入图片。其他格式已有的图片解读流程保持原规则。本轮取消 OCR 的范围是 PDF。

| 材料状态 | 含义及处理 |
| --- | --- |
| 排队／处理中 | 输入尚未准备完整，容量估算会继续变化，不能用于 AI 请求 |
| 处理完成 | 原生文本或全部 PDF 页面图片已准备完整，通常使用绿色状态；后台的 `ready` 和 `needsReview` 均显示完成。可选核对说明放在默认折叠的处理报告中，不作为警告展示；旧材料重新处理的限制另行提示 |
| 处理完成 · 超出 AI 输入容量 | 完整材料的预计输入超过 40,000 token，在课程材料库和任务编辑页的列表中使用醒目提示，旁边显示预计占用与上限；材料已保存，但不能直接用于超限 AI 请求 |
| 提取不完整 | 存在失败单元、处理范围超限或未准备内容；禁止用于生成或发布 |
| 失败 | 文件无法处理，需要重新处理或更换文件 |

PDF 重新处理会从原文件完整检查并准备，不沿用旧 OCR 断点。页面准备失败时保留错误报告，不把剩余页面当作完整输入。其他格式连续三个单元失败时停止处理。重启后未完成材料重新排队，已中断的生成任务标记失败，供教师手动重试。

模型请求并发上限为 4。包含图片的长讲义也通过 Spring AI 流式接收，再校验完整结构后保存。长讲义首段输出最多等待 5 分钟，后续空闲超时沿用本机配置，单次长响应（含有限重试）最长等待 20 分钟。页面显示实际收到的字符数，重试时重新计数；中断内容不会作为成功结果应用。连接故障、429 和服务端错误进行有限重试；身份验证或输入错误不反复重试。

### 40,000 输入上限与 64,000 总上下文

1. **文本**：展示估算值，以 UTF-8 字节数加消息开销作为保守上界；这不是精确 tokenizer 计数。
2. **图片**：按实际发送图片的尺寸，使用硅基流动 Qwen 高精度视觉输入规则估算，即 28 像素网格与平台公布的像素范围。上传 PDF 的所有页面图片均计入使用该材料的每一次 AI 请求，不再先转录为文字。[硅基流动视觉文档](https://docs.siliconflow.cn/docs/userguide/capabilities/vision)
3. **两项限制同时生效**：文本保守上界 + 图片估算不得超过 **40,000 token**；输入 + 输出预留 + 安全缓冲不得超过 **64,000 token**。统计包含课程信息、学生情况、教师提示词、材料、当前讲义（修订时）、学生答案、完整当前对话以及页面标签和消息开销。
4. **输出预留**：讲义生成保留 10,000 token 安全缓冲，输出按剩余空间预留 8,192—16,000 token；对话保留 2,048 token 安全缓冲及 1,024—4,096 token 输出。生成任务入队和模型实际发送前均进行预算检查；超限返回明确错误，不删减页面、材料或历史来绕过限制。
5. **实际用量**：成功响应后记录平台返回的 `prompt_tokens`、`completion_tokens` 与 `total_tokens`。图片计数是发送前估算，平台回传值才是实际用量。准备 PDF 时没有这类实际模型用量。[接口字段说明](https://docs.siliconflow.cn/docs/api/chat-completions-post)

容量组件展示输入上限、图片估算、剩余可用输入容量、输出预留和总上下文限制。请求中的教学上下文不携带上传状态、文件大小、存储路径或完整处理报告。64,000 是本应用的总上下文约束；平台模型窗口更大也不会放宽应用的 40,000 输入上限。

任务页提供“测试 AI 连接”和“测试图像理解”。这些按钮只有在用户点击时才会产生实际模型请求，并显示结果、模型名称和耗时。长响应显式开启流式用量统计，参见 [Spring AI 流式用量配置](https://docs.spring.io/spring-ai/reference/api/chat/openai-chat.html)。

## Windows 本机运行

需要 PowerShell 7、JDK 17、Maven、Node.js 与 MySQL。源码和 Maven Enforcer 限制为 Java 17；IDE 项目 SDK、Maven 运行 JDK、`JAVA_HOME` 应保持一致。

日常开发可按下列命令启动；2026-10-24 的运行验证使用 Java 17 启动打包后的 JAR，并使用项目自带静态服务加载前端 `dist`。

```powershell
Set-Location -LiteralPath 'C:\Users\user\Desktop\zzm\app'
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-17.0.2'
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
$env:MYSQL_USER = 'root'
$env:MYSQL_PASSWORD = Read-Host 'MySQL 密码' -MaskInput
$env:MYSQL_URL = 'jdbc:mysql://localhost:3306/aicademiya?useUnicode=true&characterEncoding=utf8&serverTimezone=UTC'
pwsh.exe -File .\start.ps1 -Component backend
```

另开一个 PowerShell 7 窗口启动前端：

```powershell
Set-Location -LiteralPath 'C:\Users\user\Desktop\zzm\app'
pwsh.exe -File .\start.ps1 -Component frontend
```
